# visalab — фоновый слой приборов на pyvisa + PyQt6

Стандартизованный фундамент для управления приборами и драйверы:

| Прибор | Профиль | Драйвер | Симулятор | Мануал |
|---|---|---|---|---|
| Генератор Siglent SDG (2 канала) | `function_generator` | `drivers/siglent_sdg.py` | `sim/siglent_sdg_sim.py` | PGen.pdf (SDG Series Programming Guide) |
| Источник ITECH IT6300 (IT6322: CH1/CH2 30 В 3 А, CH3 5 В 3 А) | `power_supply` | `drivers/itech_it6300.py` | `sim/itech_it6300_sim.py` | PSupply.pdf (IT6300 Programming Guide V1.1) |
| СВЧ-генератор Keysight PSG E8267D | `signal_generator` | `drivers/keysight_e8267d.py` | `sim/rf_generator_sim.py` | PSG SCPI Command Reference E8251-90356 |
| СВЧ-генератор R&S SMF100A | `signal_generator` | `drivers/rs_smf100a.py` | `sim/rf_generator_sim.py` | R&S SMF100A Operating Manual |
| Анализатор спектра Agilent PSA E4446A (E4440A...E4448A) | `spectrum_analyzer` | `drivers/agilent_e4446a.py` | `sim/agilent_e4446a_sim.py` | PSA User's and Programmer's Reference Vol.1 (E4440-90607) |
| Векторный анализатор Keysight PNA-L N5231A (N5230C, N5232A, N5222A) | `network_analyzer` | `drivers/keysight_n5231a.py` | `sim/keysight_n5231a_sim.py` | PNA Programming Commands (справка PNA) |
| Датчик мощности Keysight U2021XA | `power_meter` | `drivers/keysight_u2021xa.py` | `sim/keysight_u2021xa_sim.py` | U2020 X-Series Programming Guide (U2021-90003) |

Модель по `*IDN?` не определяется и не проверяется: она задаётся явно (`--model e8267d=E8267D-544`,
`--sdg-model`, `--psu-model`, таблицы `MODELS` в `drivers/__init__.py`). Без модели пределы мягкие,
и окончательное слово остаётся за прибором.

## Профили: прибор как «чёрный ящик»

Снаружи прибор виден только через **профиль своего класса** (`visalab/profiles.py`): имена ключей,
тип, единицы СИ, токены ENUM, имена действий. Как драйвер переводит это в SCPI, его внутреннее дело.
Поэтому E8267D и SMF100A для GUI и сценариев неотличимы: те же ключи, те же сигналы, одинаковое окно.

```python
proxy.set("rf.frequency", 10e9)     # одинаково для E8267D (":FREQ ...") и SMF100A ("FREQ ...")
proxy.set("am.source", "EXT")       # E8267D получит "EXT1", SMF100A - "EXT"
proxy.set("am.freq", 1e3)           # E8267D: ":AM:INT:FREQ", SMF100A: общий "LFO:FREQ"
proxy.action("all_off")             # есть у каждого источника сигнала и питания
proxy.supports("pulse.width")       # необязательная функция профиля: есть ли у этого прибора
```

Правила (проверяются при создании драйвера, нарушение = `ProfileError`, драйвер не запустится):

* ключ драйвера - либо ключ профиля, либо расширение производителя `x.*` (например `x.beep`, `x.copy_1_to_2`);
* ключ профиля имеет у драйвера тот же тип, единицу и режим (чтение/запись), ENUM - только токены профиля;
* обязательные ключи и действия профиля есть у каждого драйвера класса;
* единицы без префиксов: Hz, V, A, W, s, dBm, %, deg, rad; логические значения - `True/False`;
* канальные ключи - `ch1.*`, `ch2.*`... (у SDG были `C1.*`, теперь `ch1.*`).

`tests/test_profiles.py` прогоняет каждый драйвер из `DRIVERS` на его симуляторе и проверяет контракт;
`tests/test_rf_generators.py` проверяет, что один и тот же сценарий даёт один и тот же результат на обоих генераторах.

Профиль ВАЦ (N5231A) появится вместе с его драйвером.

### Трассы и анализатор спектра

Трасса - стандартный объект `visalab.core.Trace` (`x`, `y`, `x_unit`, `y_unit`, `meta` с RBW/VBW/детектором),
приходит обычным `param_updated("trace", Trace)`. Окно рисует её само (`TracePlot`, без внешних библиотек).

* Драйвер ведёт анализатор однократными развёртками (`INIT:CONT OFF`, `INIT;*OPC`) и публикует трассу
  только после окончания развёртки: недорисованная трасса наружу не уходит. Долгая развёртка не считается
  обрывом связи. `meas.continuous` - развёртки подряд, `single` - одна.
* Любое изменение настройки прерывает идущую развёртку и запускает новую: трасса всегда соответствует
  текущим условиям, они же записаны в `trace.meta`.
* Связанные «авто»-величины (RBW, VBW, время развёртки, старт/стоп) перечитываются после каждой записи.
* Маркер: `marker.state`, `marker.freq`, `marker.level`, действие `marker_peak`.

### Векторный анализатор

Тот же принцип, что у анализатора спектра: однократные развёртки (`SENS1:SWE:MODE SING;*OPC`), наружу
только целая трасса `Trace` (x в Hz, y в единицах формата: MLOG - dB, PHASE - deg, GDELAY - s, остальные без единиц).

* Снаружи стандартные `sparam` (S11/S21/S12/S22), `format`, `freq.start/stop/center/span`, `sweep.points`,
  `bw.if`, `source.power`, усреднение, маркер (`marker.value`, `marker_peak`, `marker_min`).
* Драйвер работает с первым измерением канала 1 (`CALC1:PAR:CAT:EXT?`) и ничего не удаляет; если измерений
  нет, создаёт `VL_MEAS` (S11) в окне 1. Смена S-параметра - `CALC1:PAR:MOD:EXT`, калибровку не трогаем.

### Ваттметр: измерение с запуском по уровню

Результаты всегда в dBm: `meas.power` (среднее, в стробе при `detector = NORMAL`), `meas.peak`, `meas.ptav` (dB).

```python
proxy.set("trig.level", -10.0)       # dBm
proxy.set("gate.start", 20e-6)       # строб от момента запуска
proxy.set("gate.length", 100e-6)
proxy.set("trig.source", "INT")      # по уровню; драйвер сам переведёт датчик в NORMal
proxy.subscribe("meas.power", on_power)   # приходит после каждого запуска
```

* `trig.source = IMM` + `meas.continuous = True` - свободный счёт, результат при каждом опросе.
* Любой другой запуск - драйвер посылает `INIT;*OPC` и ждёт бит OPC в `*ESR?` при опросе. Запроса,
  который висит до прихода запуска, нет: без сигнала окно не зависает и связь не рвётся
  (`meas.armed = True` - ждём). После измерения, если `meas.continuous`, взводится снова.
* `single` - одно измерение, `trigger` - программный запуск (`trig.source = BUS`), `abort`, `zero`, `calibrate`.
* Конфликты прибора (-221: INT при AVERage, наклон фронта не при INT/EXT) драйвер обходит сам.

## Запуск

```bash
pip install -r requirements.txt
python run_gui.py                       # все приборы из lab.json (адреса лаборатории)
python run_gui.py --e4446a lab          # один прибор, адрес из lab.json
python run_gui.py --sdg sim --psu sim   # SDG и источник на симуляторах
python run_gui.py --list                # найти адреса USB-приборов
python run_gui.py --sdg "USB0::0xF4EC::...::INSTR" --psu "USB0::0x2EC7::...::INSTR"
python run_gui.py --only psu --psu "USB0::..." --psu-model IT6322
python run_gui.py --sdg "USB0::..." --sdg-model SDG2042X
python run_gui.py --e8267d sim --smf100a sim                 # СВЧ-генераторы на симуляторах
python run_gui.py --u2021xa sim                               # датчик мощности на симуляторе
python run_gui.py --e4446a sim                                # анализатор спектра на симуляторе
python run_gui.py --pna sim                                   # векторный анализатор на симуляторе
python run_gui.py --sdg 192.168.0.3     # по LAN (VXI-11): то же, что TCPIP0::192.168.0.3::INSTR
python run_gui.py --sdg 192.168.0.3:5025  # сырой сокет: TCPIP0::192.168.0.3::5025::SOCKET
python run_gui.py --e8267d "GPIB0::19::INSTR" --model e8267d=E8267D-544
python run_gui.py --delay sdg=0.1      # пауза 100 мс между командами генератора
python -m pytest -q                     # тесты без железа
```

## Архитектура

```
 GUI-поток                                   поток прибора (QThread, свой у каждого)
 ┌──────────────────┐   сигналы-запросы       ┌──────────────────────────┐
 │ InstrumentWindow │ ─ open/set/read/action ▶│ VISAInstrument (драйвер) │──▶ Transport
 │   виджеты Param  │                         │  Param-описания, опрос,  │    ├ PyVisaTransport (USB/LAN/GPIB)
 │ InstrumentProxy  │ ◀ param_updated/status ─│  проверка ошибок         │    └ SimTransport → симулятор
 └──────────────────┘   сигналы-события       └──────────────────────────┘
```

* **`VISAInstrument`** (`core/instrument.py`) — замена `VISAClass`. Транспорт трогается только из
  потока прибора, поэтому блокировки не нужны: очередь событий Qt сама сериализует операции.
* **`InstrumentProxy`** (`core/proxy.py`) — единственное, с чем работает GUI. Создаёт поток,
  шлёт запросы сигналами, принимает события сигналами, кэширует последние значения.
  `proxy.subscribe(key, ...)` раздаёт обновления виджетам по словарю, без фильтрации по адресу.
* **`Param`** (`core/params.py`) — декларативное описание параметра: тип, единица, диапазон,
  команды записи/чтения, группа, канал. Из него драйвер пишет/читает/проверяет, а GUI строит окно.
* **`PStatus`**: `UNKNOWN → WRITING → WRITTEN | COERCED | INVALID | ERROR`. После каждой записи —
  проверка `*ESR?` (и очереди ошибок) и обратное чтение; если прибор округлил/ограничил значение,
  статус `COERCED` и в GUI оранжевая рамка.
* **Ошибки прибора** — модель IEEE 488.2: serial poll (USBTMC) → бит ESB/EAV → `*ESR?` →
  `SYST:ERR?` (ITECH) или расшифровка битов ESR / `CMR?` (Siglent, у него нет `SYST:ERR?`).
* **Подключение без `*RST`**: читаем текущее состояние прибора. Сброс — отдельная кнопка с подтверждением.
* **Пауза между командами** (`COMMAND_DELAY_S`): минимальный интервал между обменами с прибором. У SDG по умолчанию 50 мс,
  у источника 0. Меняется ключом `--sdg-delay 0.1` / `--psu-delay 0.02` или на ходу `proxy.set_command_delay(0.1)`.
  Ожидание идёт в потоке прибора, GUI не замирает.

## Что исправлено относительно VISAClass.py

| Было | Стало |
|---|---|
| Глобальная шина `signals.*`, каждый экземпляр получает все сигналы и фильтрует по адресу | У каждого прибора свои сигналы через прокси; виджеты подписываются на ключ |
| `RLock` + `lock.acquire(blocking=False)` в таймере, ресурс трогают разные потоки | Ресурс живёт в одном потоке, блокировок нет |
| `*RST` при каждом подключении (выключает выходы источника!) | Подключение только читает состояние; `*RST` — действие с подтверждением |
| `_on_write` делает `write` + `query` того же заголовка и `return` из слота | Запись → проверка ошибок → обратное чтение → статус сигналом |
| `query` дописывает `?` сам и режет префиксы ответа строкой | Явные запросы; разбор ответа в драйвере (заголовки и единицы Siglent) |
| `print` в каждом обмене и в опросе, опрос молча пропускается, если замок занят | `scpi_log`-сигнал в журнал окна; трафик опроса скрыт по умолчанию |
| Ошибка в слоте роняет приложение (PyQt6 → `qFatal`) | Все слоты под `@guarded`: исключение → сигнал `comm_error` |
| Один таймаут опроса = обрыв связи; `me.timeout` меняется туда-сюда | Обрыв после `MAX_POLL_FAILURES` подряд; таймаут задаётся один раз |
| `SYST:ERR?` в цикле `while esr & 16`: если запрос вернул `None`, `esr` не меняется и цикл не заканчивается | Очередь вычитывается до кода 0, не более 32 раз |
| `stop()` вызывает `deleteLater` и `quit` без ожидания, глобальный `ResourceManager` | `proxy.shutdown()` закрывает ресурс в потоке прибора и ждёт `thread.wait()`; RM на прибор |
| Быстрые изменения (крутилка) — каждая уходит в прибор | Запросы записи схлопываются: уходит последнее значение |

## Как добавить новый прибор

0. Если класса прибора ещё нет, сначала профиль в `visalab/profiles.py`.
1. `visalab/drivers/<прибор>.py`: класс от `VISAInstrument`, задать `NAME`, `PROFILE`,
   `STRIP_RESPONSE_HEADER = True`, если прибор повторяет заголовок в ответе (`*ESR 1`),
   `build_params()` (список `Param` с ключами профиля), `build_actions()`. Токены прибора,
   отличные от стандартных, переводятся через `Param.enum_map`. Для СВЧ-генератора достаточно
   унаследоваться от `RFSignalGenerator` и заполнить таблицу `COMMANDS`.
2. Хуки по необходимости: `read_group()` (один запрос → много параметров), `select_channel()`,
   `read_error_queue()`, `write_param()`/`read_param_raw()` для нестандартных команд,
   `on_connected()`/`on_disconnecting()`, `poll()`.
3. `visalab/sim/<прибор>_sim.py`: симулятор от `SimInstrument`, команды через `self.on("[SOURce:]VOLTage", set, get)`
   (шаблоны пишутся как в мануале).
4. Строка в `DRIVERS` (`visalab/drivers/__init__.py`) — окно и `run_gui.py` подхватят прибор.
5. Тесты в `tests/` по образцу `test_itech_it6300.py`.

## Что проверить на реальных приборах

* Номиналы IT6332/IT6333 в `IT6300_MODELS` взяты не из мануала — сверить с паспортом.
* Формат ответа `MEAS:VOLT:ALL?` (разделитель) и биты `STAT:QUES:INST:ISUMn:COND?` (CV=бит0, CC=бит1, OV=бит9)
  взяты из мануала, на приборе стоит проверить.
* У SDG проверить, отвечает ли модель на `SYST:ERR?` (в этом мануале команды нет).
* E8267D и SMF100A сделаны без доступа к PDF (сеть среды сборки их не скачивает): команды по
  PSG SCPI Command Reference и SMF100A Operating Manual. На приборе проверить в первую очередь
  `:PULM:INT:PER/PWID` (нужна опция UNU/UNW), `:ROSC:SOUR?`, ответ `POW:ALC?` у SMF100A (`AUTO`).
  FM и ΦM на приборе дают -221 Settings conflict (проверено), поэтому драйвер выключает мешающий режим сам.
* U2021XA (по мануалу U2021-90003): проверить формат ответа `TRIG:SOUR?` при INT (`INT` или `INT1`, оба понимаются),
  что `INIT;*OPC` действительно взводит OPC по окончании измерения по запуску, и время `CAL:ZERO:AUTO ONCE`
  (таймаут на обнуление 30 с).
* E4446A (по мануалу E4440-90607): время чтения трассы 8192 точки в ASCII (таймаут 5 с), что `*OPC`
  после `INIT` ловит конец развёртки (в т.ч. с усреднением), формат ответа `DET?`.
* N5231A (по справке PNA, без PDF): что `*OPC` после `SENS1:SWE:MODE SING` ловит конец развёртки
  (с усреднением тоже), формат ответа `CALC1:PAR:CAT:EXT?` (`"имя,S21"`), что `CALC1:PAR:MOD:EXT` не сбрасывает
  калибровку, предел `SENS1:SWE:POIN` (16001). Ось X считается линейной (`SENS1:SWE:TYPE LIN`).

## Новый фронтенд `visalab.ui` (в работе, пока без бэкенда)

```
pip install PyQt6-Frameless-Window
python run_ui.py                 # источник, генератор, СВЧ-генератор + окно макросов (демо)
python run_ui.py psu --compact   # одно окно, сразу компактная версия
```

* Каждый прибор - своё окно на `qframelesswindow`; интерфейс на английском.
* Окно: сверху основные действия и вывод (`ActionBar`), ниже таблица выбранных параметров (`ParamTable`).
* Две версии одного окна, переключатель в заголовке: **Full** - все настройки + таблица,
  **Compact** - только верхняя панель и таблица. Параметр попадает в таблицу по ☆ на полном экране;
  выбор и режим запоминаются (QSettings), порядок - ПКМ по строке.
* Окно знает только `WindowSpec` (ключи профилей) и `InstrumentModel` (сигналы `edit_requested`,
  `action_requested`, `connect_requested` / `set_value`, `state_changed`). Сейчас за моделью стоит
  `DemoModel` (эхо, фальшивые измерения источника); к `InstrumentProxy` подключим отдельным адаптером.
* `MacroWindow` - заготовка окна макросов.
